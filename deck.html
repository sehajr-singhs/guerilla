Machines don't run on numbers. They run on parts, and the parts draw a shape.

Guerilla is a software company building the Index of Operations, one model of a machine's parts and the connections between them that is used to monitor it, predict it and control it.

The problem02

AI is now limited by physical machines, and the models watching them fail in the same four ways.

No transfer
A model trained on one motor or robot doesn't work on the next, so every unit needs its own data.
Brittle to maintenance
Swap or recalibrate a sensor and the features drift for reasons unrelated to health.
Blind at the low level
Machines fail first as a small change in how two parts relate, which big models treat as noise.
Watching and acting don't talk
One model monitors, a separate controller acts, and they share nothing.
GuerillaThe installed base runs for decades and almost none of it gets smarter after commissioning.

How it works04

A machine is parts that pass energy to each other. Watch the connections.

The index models each part (motor, pump, joint, thermal mass) and the points where parts connect. A healthy connection conserves what crosses it. When a bearing wears or an actuator weakens it stops conserving, and that signal is called slip.

slip = ⟨ |K₀·u − a| / max( K₀·|u| , |a| ) ⟩    u = command in, a = measurement out

Slip is normalized by magnitude, so rescaling or offsetting a sensor cancels exactly. The invariance is built in, it isn't something an optimizer has to learn. The same signal tells a controller when and where to adapt.

Why it's a software business06

Every machine it reads makes the next one cheaper to bring on.

Most of physical AI is betting on collecting more hours of data. Guerilla bets on reuse.

Each deployment adds part models and connections to a shared index, so the next deployment on a similar machine is configuration instead of a new model.

That's what keeps it from being consulting, and it's why the index gets more valuable than any single install.
