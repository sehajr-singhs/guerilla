Machines don't run on numbers. They run on parts, and the parts draw a shape.
Guerilla is building the Index of Operations (IOO), the control layer for the machine age. IOO is an index of the physical operators every machine is made of, like motors, pumps, joints and thermal masses, connected at the points where they pass energy and force. Build a machine from that index and its telemetry stops being a pile of numbers and becomes a shape. That one shape is used to monitor the machine, model its dynamics, predict where it's going and control it, with a stability proof on the controller.

The problem

AI is now limited by physical things: power, the grid, data centers, factories and robots. The machines doing that work are coupled systems, and almost all machine learning on them treats them as flat tables of sensor numbers or compresses them into a video-style latent. That causes the same four failures everywhere.

  1. No transfer. A model trained on one motor, turbine or robot doesn't work on the next one, so every unit needs its own data.
  2. Brittle to maintenance. Recalibrate or swap a sensor and the features drift for reasons that have nothing to do with the machine's health.
  3. Blind at the low level. World models and vision-language-action policies treat fine-grained signal as noise, but machines fail at the low level first, as a small change in how two parts relate.
  4. Monitoring and control don't talk. One model watches, a separate controller acts, and they don't share a representation.

Meanwhile the installed base, the motors, pumps, compressors, turbines and grid assets already running, will run for decades and almost none of it gets smarter after commissioning.

The idea

At any instant a running machine is one point in a space with an axis for every variable it has, currents, torques, temperatures, pressures, positions. As it runs, the point moves. It can't go anywhere it wants, because its parts are physically coupled and energy that leaves one part has to arrive at the next. So the point traces a trajectory on a curved surface inside that space, a manifold, and that surface is the machine. IOO is built to read that surface directly.

IOO has two halves that form one object.

The Index of Operations, the state
Every variable of the machine, from microsecond motor current to slow thermal drift to the position of an arm, sits on one coordinate sheet, the great state vector Ψ. It's multi-scale, so fast local physics and slow whole-machine behavior live side by side, and it carries a slow drift coordinate so long-term wear is never thrown away.
The Index of Operators, the dynamics
A catalog of physical operator classes (DC motor, pump, thermal mass, actuator, joint). Each class has its own local geometry, a physical operating envelope, and ports where it trades energy, mass, heat or force. A machine is a composition of operators glued at their ports, written as one sparse block-diagonal matrix: each block is an operator's own dynamics, and the off-diagonal coupling fields are the interfaces. A class of machines is just a different arrangement from the same index.
The Time-Series Operator, the engine
The TSO is what reads, predicts and acts on the index. It reconstructs phase space from raw signals with delay embedding, lifts nonlinear dynamics into a space where they evolve linearly (the Koopman operator, fit with dynamic mode decomposition and a learned deep-Koopman autoencoder), learns the vector field the state flows along, and watches a data-driven Lyapunov exponent for tipping points.
The core equations

1. Sensation: the state on one sheet

Ψ(t) = [ x_drift(t) ; ψ_1(t) ; ψ_2(t) ; … ; ψ_macro(t) ]  ∈ ℝ^N(t)

x_drift tracks slow wear and absolute level. Each ψ_i is one operator's local state. N(t) can grow, because when a genuine new interaction shows up the index adds an axis for it.

2. Dynamics: a sparse block operator

A = blockdiag( K_drift, K_1, K_2, …, K_macro )  +  C          Ψ(t+1) = A Ψ(t) + B u(t)

Each K_i is a Koopman transition matrix for one operator, learned from data and kept sparse by sequentially thresholded least squares. C holds the couplings at the interfaces. Zero blocks are skipped entirely, so a robot's left foot never computes against its right ear, which is what makes the model small enough to run at the edge.

3. Monitoring: conservation slip at each interface

slip = ⟨ |K₀·u − a| / max( K₀·|u| , |a| ) ⟩        u = command in,  a = measurement out

A healthy interface conserves what crosses it. When a bearing wears or an actuator weakens, the boundary stops conserving and slip rises. Because slip is normalized by magnitude, any per-channel rescale or offset of a sensor cancels exactly (checked numerically to 1e-14). That's invariance by construction, not invariance an optimizer has to learn.

4. Prediction and control, with a stability shield

Ψ(t+τ) = exp(A·τ) Ψ(t)

u*(t) = B† ( Ψ_target − A Ψ(t) )      subject to   V(Ψ(t+1)) − V(Ψ(t)) ≤ 0

Because the dynamics are linear in the lifted space, the future is one matrix exponential instead of a long rollout, and the control move is one pseudoinverse (or a short model predictive control problem) instead of an iterative search. V is a learned Lyapunov function that rejects any command that would let the system's energy grow, the same certified-Lyapunov machinery from my NeurIPS workshop paper. Adaptation is gated by slip, so it only turns on at the interface that stopped conserving.

How it runs, end to end
  1. Multi-rate ingestion. Telemetry streams in on asynchronous clocks, so fast electrical loops can run many times before syncing with slow thermal and mechanical layers.
  2. Operator compilation. Channels are assigned to operator classes from the index, each operator gets a Riemannian metric from its block of the telemetry covariance, and operators are glued at their ports into one graph. Coupling structure can also be discovered from data with a non-parametric conditional mutual information test.
  3. Invariant projection. Each interface is read as conservation slip and each operator as a recalibration-free shape signature, with the slow drift coordinate kept alongside so wear stays visible.
  4. Lifting and adaptive basis. The TSO lifts the dynamics into Koopman coordinates, prunes dead terms, and adds a new basis term only when the residual is genuinely large, so the model grows where the machine is surprising and nowhere else.
  5. Readout. A message-passing network reads the graph hierarchically, components into subsystems into the whole machine. Each node can be a fiber bundle with separate structural, fluid, thermal and electrical subspaces, and persistent homology adds topological features at readout.
  6. Certified action. Slip-gated model predictive control on the lifted model, filtered by the Lyapunov shield, with human-readable alerts that say which subsystem and which interface.

Two directions from one index
Go deep: a world action model of machines
Stack the index hierarchically and attach it to space and time, with macro coordinates as the base and each point carrying a fiber of local physics. A visual front-end (3D Gaussian splatting or a Fourier neural operator) turns camera input into geometry on the same sheet, and a language layer turns goals into boundary constraints on the state. A fast geometric loop handles reflexes while a slower semantic loop plans. Because a robot indexes its own body as operators, a new body is a new shape, not a new dataset. Give it two rounded stubs instead of hands at a keyboard and it treats typing as geometry: tilt until the contact patch covers one key, feel for slip, correct.
Go small: fewer parameters, less data, at the edge
The physics prior does the work data would otherwise do. Graphs of tens of nodes, sparse block matrices that skip zeros, CPU-sized models that run on the machine itself on the telemetry it already streams. The long-term target is a split runtime, with global assembly on GPUs and microsecond operator loops on reconfigurable hardware.
The flywheel

Most of physical AI is betting on collecting more hours of data. Guerilla bets on reuse. Every machine IOO reads adds operators and interfaces to the index, and every new machine built from known operators starts with a prior instead of an empty model. More machines make the index better, and a better index makes the next machine cheaper to bring on. Over time the operator catalog and interface registry become an open standard, with bridges to ROS 2, MQTT and Protobuf and shared fault-injection benchmarks, so the index becomes the way machines describe themselves.

What it doesn't do yet, and the fix
  • Control is simulation-only. Fix: one frozen controller across a physical actuator swap on a bench motor and a robot joint.next 30 days
  • No stability certificate on the slip gate yet. Fix: an ISS / Lyapunov bound on slip-gated control under bounded gain error, with the CROWN tools I already use.next 60 days
  • Operators are hand-built, mostly rotating machinery. Fix: learn operators from data with extended DMD and residual basis selection.next 90 days
  • Shape is blind to slow level drift, which is real wear. Fix: the dual-scale state, a slow drift coordinate carried next to the invariant shape.designed
  • The adaptive basis grew 94× in 140 steps on a motor test. Fix: a noise-adaptive threshold (relative ε around 0.15 to 0.2) so it only grows on genuine anomalies.designed
  • On a nearly linear motor, plain least squares tied the Koopman lift (6.26 vs 6.39 RMSE). Fix: fall back to linear blocks where the machine is linear and spend lift only where it isn't.designed
  • At 9 channels a graph network adds nothing over feature stacking. Fix: scale down to plain stacking for sparse assets, so the operator is the product and the GNN is one readout.designed
  • At full data, flexible sequence models catch up. Fix: grow the coupling fields and basis with data, so the prior wins at low data and the model keeps scaling at high data.research
  • Ten-minute SCADA averages defeat everything, IOO included. That's the edge of where it applies: it needs dynamics-rate telemetry.scope
